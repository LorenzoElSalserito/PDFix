# PDFix -- Apache Deployment Guide

## Prerequisites on the server

- Apache 2.4 with `mod_rewrite` enabled
- PHP >= 7.4 with extensions: `mbstring`, `gd`
- Composer >= 2 (only needed at build time)
- Node.js >= 18 (only needed at build time)

Enable mod_rewrite if not already active:

    sudo a2enmod rewrite
    sudo systemctl restart apache2

## Option A: build locally, deploy the artifact

Run the build script on your development machine:

    ./deploy/build.sh

This produces a `dist/` directory with everything needed. Copy it to the server:

    rsync -avz --delete dist/ user@server:/var/www/pdfix/

## Option B: build on the server

Clone the repo on the server and run the build there:

    git clone <repo-url> /opt/pdfix
    cd /opt/pdfix
    ./deploy/build.sh
    cp -r dist/* /var/www/pdfix/

## Apache configuration

Copy the provided VirtualHost config:

    sudo cp deploy/apache-vhost.conf /etc/apache2/sites-available/pdfix.conf

Edit `ServerName` to match your domain, then enable the site:

    sudo a2ensite pdfix.conf
    sudo systemctl reload apache2

### What the VirtualHost does

- Points DocumentRoot to `/var/www/pdfix` (the build output).
- Enables `AllowOverride All` so the `.htaccess` can use `RewriteEngine`.
- Sets PHP upload limits (50 MB per file, 100 MB total POST body, 256 MB memory).

### What the .htaccess does

The `.htaccess` generated by the build script handles three cases:

1. If the request matches an existing file (`index.html`, `assets/*`), serve it directly.
2. If the request starts with `/api/`, route it to `api/index.php` (the PHP backend).
3. Everything else serves `index.html` for Vue.js client-side routing.

## Directory layout after deploy

    /var/www/pdfix/
    ├── .htaccess           Rewrite rules (generated by build.sh)
    ├── index.html          Vue.js SPA entry point
    ├── assets/             JS and CSS bundles
    ├── api/
    │   └── index.php       PHP API router
    ├── vendor/             Composer autoload + dependencies
    └── src/
        ├── Merger.php
        └── Converter.php

## File permissions

    sudo chown -R www-data:www-data /var/www/pdfix
    sudo find /var/www/pdfix -type d -exec chmod 755 {} \;
    sudo find /var/www/pdfix -type f -exec chmod 644 {} \;

## HTTPS (recommended)

Use Certbot to add a TLS certificate:

    sudo apt install certbot python3-certbot-apache
    sudo certbot --apache -d pdfix.example.com

## Verify

    curl -s http://pdfix.example.com/api/health | python3 -m json.tool

Expected output:

    {
        "status": "ok",
        "php": "8.x.x",
        "extensions": {
            "mbstring": true,
            "gd": true
        }
    }

Open `http://pdfix.example.com` in a browser to use the application.

## Troubleshooting

**404 on /api routes**: mod_rewrite is not enabled or AllowOverride is not set to All.

**413 Request Entity Too Large**: the PHP upload limits in the VirtualHost are being overridden. Check `/etc/php/8.x/apache2/php.ini`.

**500 on API calls**: check `sudo tail -f /var/log/apache2/pdfix-error.log`. Common causes: missing Composer dependencies (run `composer install --no-dev` inside the deploy dir), missing PHP extensions.

**Blank page**: the Vue.js build was not copied correctly. Verify that `index.html` and `assets/` exist in the DocumentRoot.
